基线为 `a7e15b19a74f064e8d9fde2bf03753845b68cf04`，旧 Release 为 `snapshot-20261116-v1`。新分支不改写旧 main，本次 Release 为 `snapshot-20261117-jetson-act-qwen`。

## 成功方式和设备分工

旧快照：成功远盖为保存轨迹回放，当天远盖 ACT 在线对照未吸起；近盖为电脑 ACT 推理，两次成功，约 9 ms；成功链路未使用 Qwen 自动调度。

本分支：两份 ACT 均在 Jetson 在线推理、两模型常驻；电脑只做 Qwen3.5-9B LoRA 状态判断并自动调度，桌面 ACT 发布入口由 `inference_remote.txt` 禁用。umie 继续提供双腕 RGB 和有线继电器桥接。

## 当前取消右臂等待，未拆分模型

每份 ACT 同时预测 14 个关节与两路吸盘，远盖、近盖共两份权重，没有新增左右臂独立模型。

曾试验 `coordinate_far_right_arm: true`：在自动远盖阶段保持右臂于确认过的归位姿态，左臂完成起抬关节条件后放行右臂 ACT；左臂/吸盘仍来自 ACT，融合和限幅保持。该轮成功，远盖 62.2 秒、近盖 31.0 秒。

用户随后要求取消，现为 **`coordinate_far_right_arm: false`**。仅改该项再次完成两盖，远盖 43.9 秒、近盖 30.7 秒。部署脚本保留现有值，不会自行重新开启。两种设置各一次成功，不足以比较长期可靠性，也不能认定等待约束是成功所必需的条件。

## Qwen 切换逻辑

1. 自动入口为 `/robot/policy/start_sequence_brain`。Qwen 判读头相机的箱体裁剪图，约 1 Hz，单次约 0.6 秒；腕相机仍用于 ACT。
2. 远盖要求 `far_open` 或 `both_open`，近盖要求 `both_open`。图像过暗或状态不确定时不触发完成。
3. 阶段至少运行 5 秒，至少 3 张不同新图像连续确认，首末间隔不少于 1.5 秒。
4. 保留 `require_manipulation_sweep_for_brain: true`，实际关节反馈必须表明翻盖动作进入收尾，电脑和 Jetson 分别检查。
5. 完成服务绑定 run ID、stage、sequence ID、适配器 SHA 和归位后的新图像时间戳，拒绝旧结果、重复或错误阶段事件。
6. 远盖完成后先停止、释放并确认吸盘，再次双臂归位、清空旧动作、启动近盖；近盖完成后停止并释放。90 秒自动阶段超时只停止，不按时间强制换模型。

关节里程碑不是箱盖检测或真空压力检测。不能把单帧视觉 `complete` 当成可以立即中断动作的信号。手动入口 `/start_sequence` 不受 Qwen 自动完成调用。

## 执行与通信变化

- 实际约 8–9 Hz 重规划，108 ms 量级计算耗时未消除；没有声称已达到桌面约 9 ms。
- 保持 50 步、20 Hz 轨迹，按观察时间戳采样，100 Hz 下发；速度上限 0.5 rad/s、加速度上限 1.0 rad/s²、倍率 1.0。
- 250 ms 动作看门狗、输入时效和跟踪误差保护未放宽。
- 保留 `guard_far_suction_release: true`：自动远盖未达到示教起抬关节区间就请求释放，短暂保持后停止，避免继续空翻。该检查不证明吸牢；显式停止和手动流程保持原语义。
- Jetson ACT 和 umie 腕相机使用有效数据网口白名单，排除模型通信不可达的专用网口；继电器仍经 umie 有线桥接，长期会话问题未被单轮成功证明已消失。
- 监督录像由 systemd 用户服务承载，逐帧记录时间，退出时附加停止请求；默认启动脚本使用该监督入口。
