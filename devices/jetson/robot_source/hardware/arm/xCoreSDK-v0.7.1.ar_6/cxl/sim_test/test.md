# 给机械臂端 Codex：AR5 伺服响应与力矩—转速测量脚本需求

这是一份可单独转交的实现说明。请先阅读机械臂端工程、SDK 和控制器文档，完成
数据采集、轨迹预览、故障处理及离线分析脚本。不要假设文中的适配层函数就是
厂商 SDK 函数，也不要猜测 IP、端口、关节方向或力矩单位。

## 1. 本次需要回答的两个问题

1. **伺服响应**：在最终部署使用的控制接口下，发送的位置/速度目标经过多久才
   体现在实际运动中？跟踪误差、相位滞后、滤波和限幅如何随速度、姿态、负载变化？
2. **力矩与转速**：任务工作区内实际用了多少力矩？厂商允许的力矩—转速包络是什么？
   普通整机运动试验不等于电机极限台架试验，不能从已观测最大力矩推断最大能力。

本阶段不用抛球、不执行训练策略。先装实际漏斗、无球测量；如需模拟携球负载，
只能在已核对载荷和安装方式后使用牢固固定的等效负载，并单独标记该工况。

## 2. 仿真侧已知信息与不能直接使用的假设

机器人：AR5 双臂，每臂 7 个关节，仿真命名 `left_joint1..7`、`right_joint1..7`。
当前任务策略输出频率为 **50 Hz**，物理仿真频率为 **200 Hz**，使用位置目标、
速度前馈及独立的重力补偿 effort；隐式驱动名义刚度/阻尼为 **500/50**。
这些不是已辨识出的真实伺服参数，SDK 能否接收相同类型的目标必须先确认。

目前仿真采用的逐轴约束如下，左右臂各一组：

| 关节 | 项目速度上界 rad/s | 项目加速度上界 rad/s² | 手册“关节力矩限额” N·m |
|---|---:|---:|---:|
| J1 | 2.175 | 15 | 182 |
| J2 | 2.175 | 7.5 | 182 |
| J3 | 2.175 | 10 | 134 |
| J4 | 2.175 | 10 | 134 |
| J5 | 2.610 | 15 | 35 |
| J6 | 2.610 | 15 | 35 |
| J7 | 2.610 | 20 | 35 |

**这张表不是实测时直接运行的速度/加速度，也不是厂商连续额定力矩表。**
实际试验取厂商、现场设置、项目约束、试验阶段限制的交集；不能提高控制器原有上限。
手册来源为《AR5_V2.0版本产品硬件安装手册-20260527》，版本 B，正文 p16。
手册该表没有给出连续/峰值分类、峰值持续时间、转速曲线或温度降额。

坐标核对事项：手册 J4 范围为 -60°～145°，现有仿真使用约 -145°～60°，
可能存在符号约定差异。必须逐关节核对控制器索引、符号、零点、单位，不可直接
把仿真中的待机姿态发送给真实机械臂。当前项目 J6/J7 命令各留在约 ±50° 内，
但仍需按真实控制器坐标检查联动工作区、其他关节和全臂碰撞空间。

用户已确认：PLA 漏斗为**两层壁、15% 填充，实测 252 g**。
仿真按每侧末端漏斗组件 252 g 应用，已从原先名义 200 g 更新；转动惯量暂按原质量分布同比缩放，
仍是未标定估计，不能当成实测值。两层壁不是 2 mm 壁厚，不能在未知喷嘴/线宽时换算。
请记录现场实际安装总质量（含连接件、传感器等，并说明是否包含它们）以及控制器中
配置的工具质量、质心和惯量；拿不到的值填 `null` 并解释。不要根据 15% 填充率
简单把实心 PLA 密度乘以 0.15 来估算工具质量或惯量。
薄壁、低填充可能引入工具柔性；若末端出现结构振动，保留视频或末端传感器数据，
不能把所有相位滞后都归因于电机伺服。

## 3. 先做只读接口调查

生成 `capabilities.json`，每一项附 SDK/控制器文档出处或实际字段名称：

- 厂商/型号、控制器和固件版本、SDK 版本、实际连接模式。
- 支持的流式控制类型：位置、速度、力矩、位置+速度前馈；要求的命令周期。
- 指令是即时设定值还是进入轨迹队列；是否有插值、滤波、lookahead、增益选项。
- SDK 调用返回表示“入队”“已接收”还是“已执行”，控制器是否有实际应用指令的时间戳。
- 反馈的原生采样率、序号和设备时间戳；主机重复读取缓存时必须能识别重复样本。
- 关节位置/速度、驱动电流、力矩、温度、母线电压、限流/限速/降额/故障字段。
- 力矩字段是输出端传感器测量、由电流估算、控制器命令，还是外力矩残差。
- 电流字段是 Iq、相电流、RMS 电流、母线电流，还是百分比；单位、符号与标定信息。
- 控制权申请/释放、受控停止、停止完成状态、通信 watchdog、SDK 超时行为。
- 关节映射与真实限制，包括 J4 符号和 J6/J7 耦合限制的核对结果。

没有实时力矩反馈也可以完成伺服响应试验。不要因此阻塞全部工作。
无法得到力矩能力包络时，明确交付“未测得”，并列出需要厂商提供的资料。

## 4. 脚本结构与实际启动方式

建议交付以下入口，名称可适配现有工程：

```text
inspect_robot_capabilities.py  # 只读能力调查和短时反馈记录
plan_servo_identification.py   # 生成轨迹、预览限位/速度/加速度/jerk、输出试验计划
run_servo_identification.py    # 通过明确 --execute 启动已检查的计划
analyze_actuator_logs.py       # 完全离线分析，不能连接/控制机器人
measurement_config.yaml       # 单位、映射、工况和现场约束
```

默认运行必须是只读或轨迹预览，不能在导入模块、连接设备或运行分析脚本时发出运动。
实际执行使用已确认的配置、计划文件和显式 `--execute`；已经授权的执行不需要反复
弹出确认框。不要自动抢占其他控制程序，不要关闭厂商限位、碰撞保护或驱动保护。

内部可定义 `RobotAdapter`，但每个方法必须映射到现场真实 SDK，注明实现来源：

```text
read_state() -> 带原始时间戳/序号/单位说明的反馈
send_setpoint(...) -> 命令、序号、主机发送起止时间、可用的设备确认信息
request_controlled_stop(reason) -> 厂商支持的受控停止流程
read_limits_and_mode() -> 实际模式、限位和保护状态
```

数据记录和绘图不能阻塞发送与保护逻辑。写盘使用有界队列；丢日志、控制周期失约
或缓冲区溢出时触发受控停止并记录原因。不要在故障后自动重连、自动继续剩余轨迹。
停止之后必须读回确认；断网情况下由预先验证的控制器侧 watchdog 处理，不能把
“Python 进程退出了”当作机器人已经停止。受控停止轨迹和耗时也必须满足现场限制。

## 5. 伺服响应试验

### 5.1 时间和载荷准备

- 使用最终计划部署的同一种命令接口、伺服模式、前馈与插值设置。
- 分开记录设备采样时间、主机收到数据的时间、主机调用命令前后时间。
  不同设备时钟未同步时，禁止直接相减后称为通信延迟。
- 优先使用原生 200～1000 Hz 反馈（以实际支持为准）。命令可为 50 Hz，
  反馈不必同频。反复轮询同一缓存样本不算提高采样率。
- 日志先静止采集至少 10 秒，统计唯一样本间隔、抖动、缺帧、重复、时钟回退和噪声。
- 记录漏斗安装、工具参数、试验前后温度。左右臂、不同姿态/负载的数据分别标识。
- 由现场选择远离限位、奇异位形和障碍物的起始姿态。进入该姿态使用已有验证过的
  运动方式，不能自动把仿真姿态或突然的位置跳变写入控制器。

### 5.2 初始小幅试验

每次只激励一个关节，其他关节用同一正常控制模式保持，同时记录整臂反馈。
首轮可从**振幅 0.5°、频率 0.1 Hz**的平滑正弦开始；这是试验计划建议，
仍受现场更严格限制约束。首轮额外限制建议为：

```text
|速度| <= 0.10 rad/s
|加速度| <= 0.30 rad/s²
|jerk| <= 1.0 rad/s³
```

还要检查整条轨迹的 TCP 速度、两臂/工具碰撞空间和停止余量，不能只检查单轴值。
振幅是相对于当前中心位置的单边振幅，不是峰峰值。所有角度在配置读入后转为 rad。

每段包含平滑进入、稳定周期、平滑退出、静止记录。不要发送裸阶跃、突然速度反转
或未受限 PRBS。开始/结束包络的导数也属于轨迹限额，不能只验中间的正弦。

### 5.3 频率与幅度覆盖

低幅数据有效且保护未触发后，再按预先检查的计划增加激励频率。建议候选频率为
`0.1, 0.25, 0.5, 1, 2, 4 Hz`，实际只选接口、现场约束允许的部分。
低频采至少 3 个稳定周期，高频采至少 5 个；每个条件建议重复 3 次。

对 `q(t)=q0+A*sin(2*pi*f*t)`，稳定段满足：

```text
v_peak = A * (2*pi*f)
a_peak = A * (2*pi*f)^2
jerk_peak = A * (2*pi*f)^3
```

高频时必须相应减小振幅，并复核进入/退出段。命令每周期至少有 10 个实际发送点；
达不到时降低激励频率。振幅缩小到低于传感器噪声时标记“不可辨识”，不能硬拟合。
首轮不必覆盖最大任务速度。扩展到更高速度必须有新的已检查试验计划和现场约束，
不能由程序为了“覆盖曲线”自行提高限制。

在各关节初步完成后，选 2～3 个经过检查的代表姿态重复关键条件，检验重力与惯量
依赖；左右臂分别测。另保留一个不同频率或幅度的平滑轨迹供离线留出验证。
连续运动依赖整臂动力学，单关节试验不能证明完整抛接轨迹可以安全运行。

### 5.4 需要分析的伺服结果

- 指令与反馈的稳态偏差、位置/速度 RMSE、最大跟踪误差。
- 每个频率的幅值比、相位滞后、重复试验散布，以及其他关节的耦合运动。
- 在信号质量允许时估计延迟和低阶闭环模型（例如一阶/二阶响应加延迟）。
- 如果没有控制器应用时间戳，只能估计“有效总滞后”；不能把它全部标成通信延迟。
- 正弦相位同时包含机械响应和纯延迟。单一频率不能唯一分离两者；需要多频数据及
  合理的延迟范围，相关峰有多个解时必须标记歧义。
- 测量速度优先用设备反馈；由位置求导时保留原始位置、滤波方法和滤波延迟。
  不使用原始位置的二次差分直接判断力矩或加速度极限。
- 用未参与拟合的整段轨迹检验预测误差。按试验段划分训练/验证，不能随机拆相邻采样点。
- 给出模型适用的姿态、幅度、速度、负载、温度与采样条件。不要把低速拟合外推到全速。

无需在实机修改内部 PID。仿真侧会用这些日志拟合等效驱动、延迟与滤波；
拟合得到的仿真刚度/阻尼不等于厂商内部 PID 参数。

## 6. 力矩—转速：按可获得证据分级完成

### A. 厂商资料（优先）

请求逐轴**关节输出端**的连续/峰值力矩—转速曲线，注明：

- 允许峰值持续时间、占空比、温度降额、供电电压；
- 正反向、驱动/制动工况是否不同，减速比和效率定义；
- 多轴同时运动是否受母线功率限制；
- 电流/力矩反馈如何换算，电机端还是输出端；
- 控制器实际限流值和保护机制。

不能把 182/134/35 N·m 三档限额当成所有转速下恒定可持续输出。

### B. 整机可完成的工作区测量

在上面的受限轨迹中同步采集速度、电流、力矩、温度、电压和状态位。
在已核对的姿态/负载下，可增加平滑的近似匀速段，分开记录加速、匀速、减速。
匀速段也有重力和摩擦负载；加速段含惯性与耦合力矩，不能当作相同工况混合拟合。

输出按**关节、方向、姿态、负载、温度**分组的速度—实测力矩散点和统计表。
明确命名为 `observed_torque_demand`，即**观测到的力矩需求**。

- 只有命令力矩时，标记 `commanded`，不能当成实测输出。
- 只有外力矩估计时，标记 `external_torque_estimate`，不能当成电机力矩。
- 只有电流且换算未标定时，交付原始电流—转速数据，`torque_nm=null`。
- 即便已知 `Kt`、减速比和效率，`tau_out≈Kt*Iq*ratio*efficiency` 也只是
  带假设的估计；记录零偏、单位、来源、传动损失和适用方向。
- 反馈最大值、95% 分位数、某次保护触发前的值，都**不是**最大可用力矩曲线。
- 限流标志或跟踪变差只说明该次工况出现约束，不足以单独确定厂商极限包络。

### C. 真正的能力包络试验（仅在已有合适台架时）

若现场已有厂商允许的可控负载台架、标定力矩传感器和温度/电源测量能力，
可按该台架的既有规程，在若干速度点测持续和短时输出。这需要独立的台架计划。

**禁止用整机堵转、撞限位、手拉机械臂、临时悬挂重物或逐步加载直到保护触发来
自动搜索极限。** 若不具备台架，就将 `available_torque_envelope.status` 写为
`unavailable` 或 `datasheet_only`，完成 A/B 级交付即可，不能编造一条曲线。

## 7. 保护与试验失效条件

执行前，从现场配置读取并核验角度、速度、加速度、jerk、TCP 速度、工作空间、
负载、跟踪误差、温度、电流、通信超时和停止条件。跟踪误差/温度/电流阈值必须
来自现场限额、厂商资料或本阶段已明确批准的值；无值时不能擅自使用表中峰值替代。

出现以下情况，受控停止、记录原因并结束该段，不自动重试：

- 反馈过期、序号/时间回退、NaN、命令周期超时、写盘队列溢出；
- 实际运动或预测停止轨迹越过限制；
- 跟踪误差持续超限、厂商限流/过温/碰撞/驱动故障；
- 模式改变、控制权丢失、急停、操作者停止。

若 SDK 可能无限阻塞，发送/读取不能阻塞独立保护；必须设置超时并依靠已验证的
控制器 watchdog。在真机试验前用 mock/replay 测试重复反馈、断流、异常值、
停止失败等路径，验证脚本不会自动恢复运动。

## 8. 统一日志格式

每次运行新建目录，不能覆盖失败记录。推荐 SI 单位；时间戳使用整数纳秒，并标明
时钟域。不同频率的命令与反馈分开存储，不能通过重采样伪造同步原始日志。

```text
run_YYYYMMDD_HHMMSS/
  capabilities.json
  metadata.json
  executed_plan.json
  commands.csv
  samples.csv
  events.jsonl
  raw_vendor/                  # 原始 SDK 数据或抓取文件（去除凭据）
  summary.json
  servo_estimates.csv
  torque_vs_speed.csv
  available_torque_envelope.json
  plots/
  README_results.md
```

`commands.csv` 每关节每次发送一行，至少：

```text
trial_id,command_seq,arm,joint_name,host_tx_start_ns,host_tx_done_ns,
device_command_applied_ns,q_cmd_rad,qd_cmd_rad_s,tau_ff_cmd_nm,mode
```

`samples.csv` 每关节每个真实反馈样本一行，至少：

```text
trial_id,sample_seq,arm,joint_name,device_sample_ns,host_rx_ns,
q_rad,qd_rad_s,torque_nm,torque_kind,current_a,current_kind,
motor_temperature_c,drive_temperature_c,bus_voltage_v,
limit_flags,fault_flags,mode
```

不支持的数值留空，JSON 中使用 `null`。`sample_seq` 若由主机生成，必须在元数据中
注明，不能冒充设备序号。保留重复样本并标记，分析时只计算真正新增的设备采样。
`tau_ff_cmd_nm` 只记录实际发送的前馈，没有发送时按接口定义填 0 或空，并解释区别。

`metadata.json` 至少记录：

- 软硬件版本、脚本版本/哈希、原始日志哈希、控制接口和周期；
- 时钟域及同步方法/误差；反馈与命令的原始单位；
- 关节索引、符号、零点映射；保护阈值和来源；
- 起始姿态、工具参数、实际质量、工况、温度；
- 控制器滤波/插值/lookahead/前馈设置；电流力矩换算来源与误差；
- 运行是否完成，所有中止和无效试验原因。

| 用实测填写 | 用实测填写 | 用实测填写 | 用实测填写 | 测量/估算/命令/无 | 用实测填写 | 用实测填写 |

`available_torque_envelope.json` 必須明确：

```json
{
  "status": "unavailable",
  "source": null,
  "joint_output_units": "Nm, rad/s",
  "continuous_curves": null,
  "peak_curves": null,
  "peak_duration_s": null,
  "temperature_and_voltage_conditions": null,
  "reason": "用实际未获得原因替换；不要把任务需求散点填进能力曲线"
}
```

验收重点：原始数据可重放；同一输入的重复响应可比较；延迟估计说明时钟和模型
假设；留出轨迹有预测误差；无法测得的参数明确保留未知。这里不要求人为给出
“已满足 sim-to-real”结论，也不要求现场重训控制策略。

## 10. 仿真端如何使用这些结果

我们会用命令—反馈轨迹拟合等效驱动响应、命令延迟和滤波，保留姿态/负载差异；
用有依据的厂商/台架能力包络替换当前未知的转速—力矩曲线，用任务需求日志检查
工作区是否落在包络内；未辨识部分采用明确的不确定范围做鲁棒性验证。
