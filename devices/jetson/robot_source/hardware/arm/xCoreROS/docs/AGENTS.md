## 后续更新流程

1. 修改或发布前，先检查远端 main、gh-pages 和线上页面。2026-09-09 核对时，本地文档
   仍在旧提交 2ef80ff；不能直接用该旧布局构建并覆盖线上新版。
2. 在最新文档源码上做增量更新。保留工作区内用户修改；必要时使用独立 worktree。
3. 先阅读最新版导航、主题、计数和生成脚本。不要直接运行旧 split-pages.mjs 把总览和详情
   恢复为旧组织方式；确认最新版文档来源及生成规则后再生成。
4. 默认只增加对应模块的接口卡片、Type 详情链接、字段/示例和计数。需要新模块时沿用
   现有组件与层级，不借机重设计导航或样式。
5. 发布前构建并检查新增 Type 链接、模块锚点、计数，以及右侧导航点击后仍在当前页面的行为。

本文件记录用户偏好，不代表要求每次新增功能都自动发布站点；按当次任务的发布授权执行。
