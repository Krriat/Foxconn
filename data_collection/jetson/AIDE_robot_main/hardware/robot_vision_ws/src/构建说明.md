# Robot Vision ROS 2 构建与交付指南

| 文档属性 | 值 |
| --- | --- |
| 文档版本 | 1.0 |
| 适用软件 | Robot Vision 0.1.x |
| 适用平台 | Ubuntu 22.04 / ROS 2 Humble |
| 最后更新 | 2026-09-10 |

## 1. 文档范围

本文档用于在 Ubuntu 22.04 / ROS 2 Humble 环境中构建、测试和交付
Robot Vision 工作空间。运行、验收和故障处理见《使用与验收手册》。

当前工作空间：

```text
/home/niic/aide/hardware/robot_vision_ws
```

本文命令统一使用以下环境变量：

```bash
export ROBOT_VISION_WS=/home/niic/aide/hardware/robot_vision_ws
```

包职责：

| 包 | 职责 |
| --- | --- |
| `robot_camera_msgs` | `CameraStatus` 消息和 `GetCameraInfo` 服务定义 |
| `robot_vision_bringup` | 读取相机注册表，启动多个 RealSense 节点和管理节点 |
| `robot_vision_core` | 配置校验、相机健康监测、查询服务及感知节点 |
| `robot_vision_tools` | RGB-D 数据、内参和时间同步验证工具 |

## 2. 基线环境

已验证的基线为：

| 组件 | 版本 |
| --- | --- |
| Ubuntu | 22.04 |
| ROS 2 | Humble |
| Python | 3.10 |
| librealsense | 2.57.7 |
| realsense2_camera | 4.57.7 |

ROS 2 Humble 必须使用系统 Python 3.10。Miniconda/Anaconda 中的 Python
3.11 或更高版本可能导致 `rosidl_adapter`、`rclpy` 或 `em` 导入失败。

构建前检查：

```bash
conda deactivate 2>/dev/null || true
source /opt/ros/humble/setup.bash

which python3
python3 --version
ros2 pkg prefix realsense2_camera
```

期望 `python3` 为 `/usr/bin/python3`，版本为 `3.10.x`。

## 3. 安装依赖

首次部署时安装基础工具：

```bash
sudo apt update
sudo apt install -y \
  python3-colcon-common-extensions \
  python3-rosdep \
  python3-yaml \
  ros-humble-realsense2-camera \
  ros-humble-message-filters \
  ros-humble-rqt-image-view
```

如尚未初始化 rosdep：

```bash
sudo rosdep init
rosdep update
```

安装工作空间声明的依赖：

```bash
cd "$ROBOT_VISION_WS"
source /opt/ros/humble/setup.bash

rosdep install \
  --from-paths src \
  --ignore-src \
  --rosdistro humble \
  -r \
  -y
```

`rosdep` 不应在 Conda 环境内运行，也不应使用 `sudo colcon build`。

## 4. 构建前检查

### 4.1 检查源码包

```bash
cd "$ROBOT_VISION_WS"
colcon list
```

至少应识别：

```text
robot_camera_msgs
robot_vision_bringup
robot_vision_core
robot_vision_tools
```

### 4.2 检查相机注册表

配置文件：

```text
src/robot_vision_bringup/config/cameras.yaml
```

查看当前 USB 设备序列号：

```bash
rs-enumerate-devices | grep -E "Name|Serial Number"
```

每台 `enabled: true` 的相机必须满足：

- `serial_no` 与实机一致，且不是 `REPLACE_*` 占位值。
- `camera_name` 和 `serial_no` 在所有已启用相机中唯一。
- `align_depth: true` 时同时启用 color 和 depth。
- 启用 depth 时 `depth.scale_m_per_unit` 为正数。
- 已启用流的 image 和 CameraInfo 话题完整。

使用项目内置校验器检查：

```bash
PYTHONPATH=$PWD/src/robot_vision_core python3 -c \
  "from robot_vision_core.camera_registry import load_camera_registry; load_camera_registry('src/robot_vision_bringup/config/cameras.yaml'); print('camera registry: OK')"
```

## 5. 构建

### 5.1 标准工作空间构建

```bash
cd "$ROBOT_VISION_WS"
conda deactivate 2>/dev/null || true
source /opt/ros/humble/setup.bash

colcon build \
  --symlink-install
```

`--symlink-install` 便于 Python 源码迭代。修改 `.msg`、`.srv`、`package.xml`、
`CMakeLists.txt` 或安装规则后，仍必须重新构建。

### 5.2 仅构建相机管理链路

```bash
colcon build \
  --symlink-install \
  --packages-up-to robot_vision_bringup
```

该命令不会构建 `robot_vision_tools`。如需使用 `rgbd_probe`，请执行第 5.1 节的
标准工作空间构建。构建成功的标准是 summary 中没有 `failed` 或 `aborted`。

### 5.3 切换工作空间路径或构建模式

工作空间被移动，或从普通安装切换到 `--symlink-install` 时，旧生成物不能
复用。可仅清理本项目相关包：

```bash
rm -rf \
  build/robot_camera_msgs \
  build/robot_vision_core \
  build/robot_vision_bringup \
  install/robot_camera_msgs \
  install/robot_vision_core \
  install/robot_vision_bringup
```

上述目标均为 colcon 生成物；不要删除 `src` 目录。清理后重新执行标准构建。

如需保留原生成物，可使用独立目录：

```bash
colcon --log-base log_validation build \
  --build-base build_validation \
  --install-base install_validation \
  --symlink-install \
  --packages-up-to robot_vision_bringup
```

## 6. 构建后验证

加载 overlay：

```bash
source /opt/ros/humble/setup.bash
source "$ROBOT_VISION_WS/install/setup.bash"
```

确认包来自当前工作空间：

```bash
ros2 pkg prefix robot_camera_msgs
ros2 pkg prefix robot_vision_core
ros2 pkg prefix robot_vision_bringup
```

检查可执行程序和 launch 参数：

```bash
ros2 pkg executables robot_vision_core | grep camera_manager
ros2 launch robot_vision_bringup multi_realsense.launch.py --show-args

应显示以下主要参数：

| 参数 | 默认值 |
| --- | ---: |
| `start_camera_manager` | `true` |
| `publish_rate_hz` | `2.0` |
| `stale_threshold_sec` | `2.0` |
| `offline_threshold_sec` | `10.0` |
| `startup_grace_sec` | `5.0` |
| `hz_window_sec` | `5.0` |

执行相机注册表和健康状态回归测试：

期望结果：

```

执行包级测试：

```bash
colcon test --packages-select robot_vision_core

```

注意：当前 `robot_vision_core` 内的旧 ArUco/YOLO 节点存在已知 lint 问题；相机管理

为最终准入条件。

## 8. 常见构建故障

### 8.1 `CMakeCache.txt directory is different`

原因：工作空间曾在其他路径构建。

处理：按第 5.3 节清理对应包的 `build` 和 `install` 生成物后重建。

### 8.2 `failed to create symbolic link ... is a directory`

原因：普通安装生成的目录与 `--symlink-install` 需要创建的软链接冲突。
`--cmake-clean-cache` 不会删除该目录。

处理：按第 5.3 节清理对应生成物，或改用独立 build/install 目录。

### 8.3 `ModuleNotFoundError: em/rclpy/lark`

原因：Conda Python 覆盖了 ROS 2 Humble 的 Python 3.10 环境。

检查并处理：

```bash
conda deactivate
source /opt/ros/humble/setup.bash
which python3
python3 --version
```

### 8.4 修改后仍运行旧版本

检查 overlay 顺序：

```bash
source /opt/ros/humble/setup.bash
source "$ROBOT_VISION_WS/install/setup.bash"
ros2 pkg prefix robot_vision_bringup
```

如修改的是安装规则、消息、服务或配置文件，请重新构建。调试配置时也可在
launch 命令中显式传入源码 YAML 的绝对路径。

## 9. 交付检查清单

发布或部署前应确认：

- 使用 ROS 2 Humble 和 Python 3.10 构建。
- `rosdep install` 无未解决依赖。
- 相机注册表通过校验，序列号与实机一致。
- `colcon build` 无失败包。
- 相机管理回归测试全部通过。
- 安装包中不包含 `__pycache__` 或 `.pyc` 临时文件。
- 按《使用与验收手册》完成真机话题、帧率、状态、服务和掉线恢复验收。
