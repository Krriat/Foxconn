# Robot Vision ROS 2 使用与验收手册

| 文档属性 | 值 |
| --- | --- |
| 文档版本 | 1.0 |
| 适用软件 | Robot Vision 0.1.x |
| 适用平台 | Ubuntu 22.04 / ROS 2 Humble |
| 最后更新 | 2026-09-10 |

## 1. 文档范围

本文档面向调试、测试和运维人员，说明如何配置、启动、验收和排查多台
Intel RealSense 相机。构建环境和依赖安装见《构建与交付指南》。

系统由两层组成：

1. `robot_vision_bringup` 根据注册表启动每台 RealSense 驱动。
2. `/robot/vision/camera_manager` 监测已启用流，发布健康状态并提供查询服务。

本文命令统一使用以下环境变量：

```bash
export ROBOT_VISION_WS=/home/niic/aide/hardware/robot_vision_ws
```

## 2. 运行前条件

每个新终端都需加载 ROS 2 和工作空间 overlay：

```bash
conda deactivate 2>/dev/null || true
source /opt/ros/humble/setup.bash
source "$ROBOT_VISION_WS/install/setup.bash"
```

确认相机已被系统识别：

```bash
rs-enumerate-devices | grep -E "Name|Serial Number|Usb Type Descriptor"
```

确认序列号与注册表一致：

```text
$ROBOT_VISION_WS/src/robot_vision_bringup/config/cameras.yaml
```

同一台相机同一时间只能由一个进程占用。启动前关闭 `realsense-viewer`、其他
`realsense2_camera` 节点和宿主机上的相机应用。

## 3. 相机注册表

注册表为相机身份和 ROS 接口的唯一配置源。单台相机的关键字段示例：

```yaml
cameras:
  head:
    enabled: true
    verified: true
    camera_name: "head"
    semantic_location: "head"
    model: "D435i"
    serial_no: "136622073022"

    streams:
      enable_color: true
      enable_depth: true
      align_depth: true
      pointcloud: false
      enable_sync: false

    profiles:
      color: "640x480x15"
      depth: "640x480x15"
```

字段说明：

| 字段 | 说明 |
| --- | --- |
| `enabled` | 是否在本次 bringup 中启动 |
| `verified` | 设备身份和配置是否经过人工确认；当前仅作记录 |
| `camera_name` | ROS 节点名、话题根路径及 RealSense frame 前缀 |
| `serial_no` | 相机硬件序列号 |
| `align_depth` | 生成对齐到彩色光学坐标系的深度图 |
| `enable_sync` | RealSense 节点内的流同步，不代表多相机硬件同步 |
| `profiles` | 分辨率与帧率；未填写时使用驱动默认值 |

生产环境建议显式填写 profile，不依赖驱动版本的默认值。虚拟机或 USB 带宽受限
时，建议从 `640x480x15` 开始验证。

## 4. 启动系统

### 4.1 使用安装目录中的默认配置

```bash
ros2 launch robot_vision_bringup multi_realsense.launch.py
```

适用于已经构建并完成交付的配置。

### 4.2 调试时使用源码配置

```bash
ros2 launch robot_vision_bringup multi_realsense.launch.py \
  camera_registry_file:="$ROBOT_VISION_WS/src/robot_vision_bringup/config/cameras.yaml"
```

该方式修改 YAML 后无需重新构建，适合相机接入调试。

### 4.3 覆盖健康检测参数

```bash
ros2 launch robot_vision_bringup multi_realsense.launch.py \
  camera_registry_file:="$ROBOT_VISION_WS/src/robot_vision_bringup/config/cameras.yaml" \
  publish_rate_hz:=2.0 \
  stale_threshold_sec:=2.0 \
  offline_threshold_sec:=10.0 \
  startup_grace_sec:=5.0 \
  hz_window_sec:=5.0
```

约束：`offline_threshold_sec` 必须大于 `stale_threshold_sec`，频率和时间窗口必须为
正数。

### 4.4 仅启动相机驱动

```bash
ros2 launch robot_vision_bringup multi_realsense.launch.py \
  start_camera_manager:=false
```

该模式适用于隔离排查驱动或 USB 问题。

## 5. 启动日志判定

正常启动应出现：

```text
Starting camera 'head'
Device with serial number ... was found
RealSense Node Is Up!
Monitoring camera 'head'
Camera status publisher started
GetCameraInfo service ready
[head] state: OK
```

以下日志通常不是致命错误：

```text
No valid configuration file found at ~/.realsense-config.json loading defaults
JSON file is not provided
```

如持续出现 `Frames didn't arrived within 5 seconds`，则实际图像流已异常，不能按正常
启动验收。

## 6. 运行验收

建议在第二个终端按以下顺序执行。

| 验收项 | 通过标准 |
| --- | --- |
| 设备 | 序列号与注册表一致，USB 3.x 连接 |
| 节点 | 相机节点和 `camera_manager` 同时存在 |
| 数据流 | 所有已启用流持续产生数据，帧率接近配置值 |
| 坐标系 | 消息 `frame_id` 与注册表一致 |
| 健康状态 | 稳定进入 `OK`，无周期性 `STALE` |
| 查询服务 | `exists` 和 `intrinsics_available` 均为 `true` |

### 6.1 节点验收

```bash
ros2 node list | sort
```

对于 `head` 相机，应包含：

```text
/robot/sensors/cameras/head
/robot/vision/camera_manager
```

### 6.2 话题验收

```bash
ros2 topic list | grep '^/robot/sensors/cameras/' | sort
```

启用 color、depth 和 aligned depth 时，核心话题为：

```text
/robot/sensors/cameras/head/color/image_raw
/robot/sensors/cameras/head/color/camera_info
/robot/sensors/cameras/head/depth/image_rect_raw
/robot/sensors/cameras/head/depth/camera_info
/robot/sensors/cameras/head/aligned_depth_to_color/image_raw
/robot/sensors/cameras/head/aligned_depth_to_color/camera_info
```

### 6.3 帧率验收

```bash
ros2 topic hz /robot/sensors/cameras/head/color/image_raw
```

```bash
ros2 topic hz /robot/sensors/cameras/head/depth/image_rect_raw
```

```bash
ros2 topic hz \
  /robot/sensors/cameras/head/aligned_depth_to_color/image_raw
```

实测帧率应接近 YAML 中的 profile，且不应连续出现 5 秒无帧。

### 6.4 frame_id 验收

```bash
ros2 topic echo \
  /robot/sensors/cameras/head/color/image_raw \
  --field header \
  --once
```

`frame_id` 应与注册表的 `frames.color_optical` 一致。对齐深度应使用彩色光学
坐标系。

### 6.5 图像可视化

```bash
rqt_image_view
```

可分别选择彩色、原始深度和对齐深度话题。也可使用 RViz2 的 `Image` 显示项。

## 7. 健康状态

查看单帧状态：

```bash
ros2 topic echo /robot/vision/camera_status --once
```

持续监视：

```bash
ros2 topic echo /robot/vision/camera_status
```

该话题每条消息表示一台相机。多相机运行时，订阅方必须通过 `camera_id`
区分相机，不应假设话题中只有一个数据源。

状态码：

| 值 | 名称 | 含义 |
| ---: | --- | --- |
| 0 | `UNKNOWN` | 启动宽限期内，尚未收齐已启用流 |
| 1 | `OK` | 所有已启用流均在 stale 阈值内更新 |
| 2 | `STALE` | 部分流超时，或全部流刚停止但未达 offline 阈值 |
| 3 | `OFFLINE` | 从未收到数据，或所有流超过 offline 阈值未更新 |
| 4 | `ERROR` | 保留给设备或配置一致性错误 |

关键字段：

| 字段 | 含义 |
| --- | --- |
| `color_stream_ok` | 彩色流是否新鲜 |
| `depth_stream_ok` | 原始深度流是否新鲜 |
| `aligned_depth_ok` | 对齐深度流是否新鲜 |
| `last_hz` | 滑动窗口内的彩色图帧率 |
| `last_seen_age_sec` | 任一已启用流最新一帧的到达年龄 |
| `expected_scale_m_per_unit` | YAML 中的期望深度比例 |
| `measured_scale_m_per_unit` | 设备 API 实测值；当前未接入时为 `0.0` |

注意：关闭的流对应 `*_ok` 字段为 `false`，但不参与整体状态判定。

## 8. 查询相机信息

```bash
ros2 service call \
  /robot/vision/get_camera_info \
  robot_camera_msgs/srv/GetCameraInfo \
  "{camera_id: 'head'}"
```

正常运行时应关注：

- `exists: true`。
- `intrinsics_available: true`。
- `state: 1`。
- `width`/`height` 与实际图像一致。
- 话题和 optical frame 与注册表一致。

`extrinsics_available: false` 在尚未接入相机到机器人基座外参时属于预期结果。

## 9. RGB-D 数据链路验证

```bash
ros2 run robot_vision_tools rgbd_probe \
  --ros-args \
  -p camera_root:=/robot/sensors/cameras/head
```

工具会近似同步彩色图和对齐深度图，周期输出：

- 彩色/深度分辨率和 encoding。
- 两帧时间差。
- 中心像素原始深度值。
- `fx`/`fy`/`cx`/`cy` 内参。

对 `16UC1` 深度图，米制距离计算为：

```text
depth_m = depth_raw * scale_m_per_unit
```

原始值 `0` 表示无效深度，不能当作 0 米。

## 10. 掉线与恢复验收

在可控的测试环境中执行：

1. 确认相机当前为 `OK`。
2. 持续订阅 `/robot/vision/camera_status`。
3. 断开相机 USB。
4. 默认约 2 秒后应进入 `STALE`。
5. 默认约 10 秒后应进入 `OFFLINE`，`last_hz` 降为 0。
6. 重新接入 USB，驱动重连成功后应恢复 `OK`。

本测试会中断视觉数据，不得在机器人运动、导航或抓取任务期间执行。

## 11. 添加或启用相机

1. 使用 `rs-enumerate-devices` 获取型号和序列号。
2. 在 `cameras.yaml` 中新增或完善独立条目。
3. 为每台相机分配唯一 `camera_name`、`serial_no` 和 frame 前缀。
4. 首次以低带宽 profile 验证单机。
5. 单机通过后设置 `enabled: true`，再执行多机联调。
6. 逐台验收节点、话题、帧率、frame、健康状态和服务。

多机部署时还应评估 USB 控制器总带宽。高分辨率相机宜分配到不同的物理 USB
控制器，并在系统满负荷时重复帧率和掉帧验收。

仅编辑安装目录中的 YAML 会在下次构建时被覆盖。持久修改应保存在 `src`
目录的注册表中。

## 12. 常见运行故障

### 12.1 相机未找到

现象：驱动等待设备，管理器最终报 `OFFLINE`。

检查：

```bash
rs-enumerate-devices
```

核对 YAML 序列号、USB 连接和虚拟机设备归属。

### 12.2 彩色正常，深度或对齐深度 `STALE`

先分别执行 `ros2 topic hz` 确认原始深度和 aligned depth。如驱动报
`Frames didn't arrived within 5 seconds`：

1. 将 color/depth profile 降到 `640x480x15`。
2. 暂时设置 `enable_sync: false`。
3. 如仍异常，暂时设置 `align_depth: false` 隔离检查原始深度流。
4. 使用 USB 3.x 直连端口，避免 Hub，关闭其他占用相机的进程。
5. 在虚拟机中确认 USB 3.x 控制器和设备独占透传已启用。

检查 Linux USB 日志：

```bash
dmesg -T | grep -iE "usb|uvc|reset|bandwidth" | tail -n 100
```

### 12.3 状态一直是 `UNKNOWN`

- 确认 `startup_grace_sec` 没有设置过大。
- 确认系统时钟没有向后跳变。
- 确认 YAML 中启用流的话题与 `ros2 topic list` 一致。

### 12.4 话题存在但收不到数据

```bash
ros2 topic info -v /robot/sensors/cameras/head/depth/image_rect_raw
```

检查 publisher/subscriber 数量和 QoS。同时确认所有终端的 `ROS_DOMAIN_ID` 一致。

### 12.5 TF 或外参不可用

`planned_target_frames` 只是计划使用的目标坐标系，不会自动创建 TF。当前
`camera_manager` 也不会生成相机到 `base_link` 的外参。机械臂或导航使用前必须
完成外参标定并由独立 TF 发布器提供变换。

## 13. 停止与安全

在启动 launch 的终端按 `Ctrl+C`，等待 RealSense 节点和 `camera_manager` 正常退出。
不要在正常退出完成前立即重复启动，否则 USB 设备可能仍被旧进程占用。

安全约束：

- 任务规划、导航或抓取不应在关键相机为 `STALE`/`OFFLINE` 时继续执行。
- `CameraStatus` 是数据流健康指标，不替代图像质量、标定精度和视场遮挡检查。
- 多相机融合不应将 `enable_sync` 当作跨相机硬件同步。
- `measured_scale_m_per_unit == 0.0` 表示深度比例尚未从设备 API 实测。
- `extrinsics_available == false` 时不得将服务返回的全零矩阵当作有效外参。
