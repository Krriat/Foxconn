## 切换依据

`native/timed_policy.hpp` 的 `ContactSpeed` 只根据已验证示教中的关节姿态划分速度保护区，不识别箱盖完成，也不把继电器开启当作吸牢。

- 远盖：左臂 J2 达到 30°前后进入慢档；看到右臂翻盖关节运动并且两臂撤离后恢复快档。
- 近盖：左臂 J4 达到 114°前后进入慢档；右臂完成起抬运动并撤离后恢复快档。
- 阶段只按“接近 → 接触与抬盖 → 撤离”前进，每个新 run ID 重置；没有固定秒数强制推进动作。
- 目标倍率以每秒最多变化 2.0 的速率过渡，1.5 ↔ 1.0 约需 0.25 秒；原限幅器继续约束关节速度与加速度。

这些阈值来自当前机器人和箱子示教，仅用于本次速度对照；它们不构成吸附检测或通用任务阶段识别。

## 连续动作时钟

新 `ActionClock` 累计动作时间。每个预测块的采样下标按两个时刻的累计动作时间差计算：

```text
index = [action_clock(execution_time) - action_clock(observation_time)] / 50ms
```

因此切换速度不会重算过去的时间，也不会把已有预测块的下标突然倒退。所有动作块和吸盘目标共享这一映射。相机/推理/通信时间戳与过期保护仍使用真实时间。

配置为 `execution_speed_profile: contact_slow_v1`，`execution_speed_scale: 1.5` 表示快档倍率。日志中的 `effective_execution_speed_scale` 是当时实际倍率，`motion_speed_phase` 表示姿态保护区。原生驱动、推理、执行器需要一致的 profile 标识才允许启动。

## 为什么之前会停滞

统一 1.5 倍成功/失败两轮的推理中位耗时均约 10 毫秒，日志没有计算超时。失败轮未来动作本身缺少有效的右臂接力目标，实际关节也跟上了这些小幅指令。

`input_ablation/report.json` 的离线输入互换显示，保持失败关节状态，仅换入成功三路图像，右臂 J2 未来约 2 秒的推进从接近 0°恢复到约 14°；成功状态配失败图像也会抑制推进。这证明模型输出对接触图像敏感，尚未区分是哪种盖面形变、接触角度或视觉特征触发了差异。互换可能产生不一致的图像/状态组合，因此不是物理因果证明。

当前合理假设是：执行变快后，图像反馈之间的接触变化增加，策略更容易落入没有继续抬盖的小幅调整；降速提供更多反馈修正机会。本次成功支持继续验证这个假设，不能把它当作唯一已证明的原因。
